# Pilot and Usability Route

Use this route to learn whether practitioners can apply the assets without the
author silently repairing the instructions.

## Status ladder

Use only the highest supported label:

1. **Prepared** — materials exist.
2. **Piloted** — at least one session ran and observations were recorded.
3. **Revised** — materials changed in response to recorded evidence.
4. **Repeated** — a revised version ran again.
5. **Practitioner-tested** — the named protocol and evidence threshold were
   satisfied.

This repository is currently **prepared**, except where a file explicitly says
otherwise. The existing blinded result log is an unpopulated evidence
structure, not a completed test.

## First pilot

1. Give two to four participants the [Failure Lab](FAILURE-LAB.md) and only the
   linked assets.
2. Allow 45–60 minutes; record role and relevant experience without collecting
   unnecessary personal data.
3. Do not explain a field until the participant has recorded where they became
   blocked.
4. Ask an outside-role participant to explain the promise, owner, recovery,
   and closure evidence.
5. Record omissions, divergent interpretations, time to first useful artifact,
   and any false confidence.
6. Log evidence using
   [the blinded practitioner result structure](examples/blinded-practitioner-result-log.md).

## No-result rule

Do not convert a constructed scenario, completed template, repository
validation, or author walkthrough into a practitioner result. Publish negative
and boundary findings with successful outcomes.
